---
title: Updating
description: Upgrade AirTrail to a new version, and roll back if needed.
---

AirTrail shows a notice in the app when a new version is available, to the owner and administrators by default. Read the [release notes](https://github.com/JohanOhly/AirTrail/releases) before updating, especially for a new major version.

<Callout type="warn">
  Take a [backup](/docs/administration/backup) before every update. Database
  migrations run forward only, so going back to an older version means
  restoring the backup taken before the update.
</Callout>

## Docker Compose

In the directory with `docker-compose.yml` and `.env`, run:

```bash title="Update AirTrail"
docker compose pull
docker compose up -d
```

The container applies database migrations automatically when it starts. Check `docker compose logs airtrail` if the app does not come back up.

### Pinning a version

The Compose file uses the `latest` tag, which moves to each new release when you pull. To update only when you choose, pin a specific version in `docker-compose.yml`:

```yaml
  airtrail:
    image: johly/airtrail:v3.12.0
```

To update, change the tag to the new version and run the commands above. A major-version tag such as `v3` follows new releases within that major version but never jumps to the next one, which avoids surprise breaking changes. Available tags are listed on [Docker Hub](https://hub.docker.com/r/johly/airtrail/tags).

### Rolling back

1. Stop AirTrail with `docker compose down`.
2. Set the image tag back to the version you were running before.
3. Restore the database backup taken before the update, as described in [Backup and restore](/docs/administration/backup#restore).
4. Start AirTrail with `docker compose up -d`.

## Portainer

Open the stack, then **Editor → Update the stack** with **Re-pull image and redeploy** enabled.

## Manual installation

Stop AirTrail, then in the installation directory:

```bash
git fetch --tags
git checkout "$(git describe --tags "$(git rev-list --tags --max-count=1)")"
bun install
bun run build
bun run db:migrate-deploy
```

Start AirTrail again, for example with `sudo systemctl start airtrail`.

<Callout type="warn">
  Always run `db:migrate-deploy` after building. Starting a new version against
  an old database schema causes errors and can lose data.
</Callout>

If you use the optional airport map layer, copy the latest `airport-overlay.pmtiles` into `static/` again before `bun run build`. See [Manual installation](/docs/install/manual).
