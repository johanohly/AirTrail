Once AirTrail is running, open the URL you set as `ORIGIN`. With the default Docker setup on your local network that is `http://<server-address>:3000`.

<Callout>
  If the page does not load or sign-in fails straight away, check
  [Troubleshooting](/docs/administration/troubleshooting). The most common cause
  is an `ORIGIN` that does not match the address in the browser.
</Callout>

## Create the owner account

The first visit opens the **Welcome** screen, where you create the first account. This account is the **owner**: it has every permission and its role can never be changed or removed. Choose a strong password.

If you lose access to the owner account, reset its password with the [admin CLI](/docs/administration/admin-cli#reset-password).

## Add other people

Everyone who uses the instance gets their own account and flight history. To add someone, open **Settings → Users** and click **Add user**. Choose their username, password, name and **Role**:

- **User** manages their own flights and account.
- **Administrator** can also manage other users, all flights, reference data and instance settings.

You can change these roles or create your own under **Settings → Roles**. See [Roles and permissions](/docs/administration/roles).

To let people sign in with an existing account from Authentik, Keycloak, Google or another OpenID Connect provider instead, set up [OAuth](/docs/features/oauth).

## Add flights

Start adding flights to watch the map fill up. You can [add flights by hand](/docs/features/add-flight) or [import them](/docs/features/import) from other apps and trackers.

## Recommended next steps

- Put the instance behind a [reverse proxy](/docs/install/reverse-proxy) with HTTPS before exposing it to the internet.
- Set up [backups](/docs/administration/backup).
- Optionally add an [AeroDataBox](/docs/integrations/aerodatabox) key for better flight lookups.
