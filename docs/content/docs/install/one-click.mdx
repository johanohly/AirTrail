The template deploys AirTrail with a PostgreSQL database on [Railway](https://railway.com), a paid hosting platform. It keeps `ORIGIN` in sync with the service's public domain, including a custom domain you add in Railway, and attaches persistent storage for the database and uploads, so there is nothing to configure. When the deployment finishes, open the service's URL and follow the [post-installation](/docs/install/post-installation) steps.

## Install script

<Callout title="Experimental" type="warn">
  The script is a shortcut for the [Docker Compose](/docs/install/docker-compose)
  installation. Use the manual Compose steps if it does not work on your
  system.
</Callout>

The script needs `curl`, Docker and Docker Compose v2 on Linux or macOS. Run it in the directory where you want AirTrail's files:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/JohanOhly/AirTrail/main/scripts/install.sh)
```

It will:

- create an `airtrail` directory and download `docker-compose.yml` and `.env` into it
- generate a random database password and write it to both `DB_PASSWORD` and `DB_URL`
- ask for the URL you will open AirTrail at and save it as `ORIGIN`
- start AirTrail with `docker compose up -d`

When it finishes, follow the [post-installation](/docs/install/post-installation) steps. The resulting installation is a normal Docker Compose setup, so [updating](/docs/install/updating) and [backups](/docs/administration/backup) work the same way.
